protected keyword
    not open to the public, BUT objects/functions can be invoked by the derived class and itself (family only!)
    it's a mix between public and private.

virtual keyword
    virtual means it is expected to be overriden (you can use the override keyword on the intended function)

    as an example:
        struct Hey
        { virtual print(); }
        struct Bye : Hey
        { print() override; }

        main()
        {
            Hey* word = new Bye(); // the reason we can do this is because a Bye object is a Hey object
            word.print(); // this will call the print() in struct 'Bye', NOT 'Hey' -- omitting the virtual will call print() in struct 'Hey'.
        } // As a heads up, keyword 'new' creates the object on the heap instead of the stack -- it's like malloc.

explicit keyword
    explicit means the object cannot be implicitly converted.
        So, in the case of constructors: whenever a value gets implicitly converted to a type (like for passing an rvalue into a function call)
        If the constructor is like:
        StructObj(int guh), and you have a function like, print(StructObj buh), then you can call print(10) BECAUSE the constructor is able to construct a structObj with an int
        HOWEVER, writing explicit StructObj(int guh) PREVENTS the compiler from doing that implicit conversion, so now you must call print like: print(StructObj(10)) -- you must be EXPLICIT.
        this also includes for initializing and setting values: you cant just do StructObj obj = 10, you MUST do StructObj obj = StructObj(10)


'...' operator (formally called 'Ellipsis')
    which allows you to accept an arbitrary amount of arguments in a function -- it's sort of like argv in call
    The way this code snippet works is like this:

            template<typename T, typename... Args>
        T* AddComponent(Args&&... args) {
            static_assert(std::is_base_of<Component, T>::value, "T must derive from Component");
            // Create new component
            auto component = std::make_unique<T>(std::forward<Args>(args)...); }

        AddComponent accepts ANY type of args, but the type T HAS to have a constructor that accepts those EXACT args types
        This makes a SINGLE component of type T, where the component of type T was constructed with those args.

        The way you INVOKE this function to begin with is like so: someEntityObject.AddComponent<ComponentType>(A, Bunch, of, Args, Needed, to, Construct, ComponentType!)
            The <> operator explicitly states what type the typename T will be -- you've used it for static_cast!


static_assert
    Static: it's for the compiler itself. While compiling, it the condition provided in the () arguments are FALSE, the compiler stops building your program altogether -- preventing you from running!
    So, if static_assert(std::is_base_of<Component, T>::value, "T must derive from Component") is false -- where Component is NOT the base class of derived class Type T (T is not derived from Component) -- then the compiler stops compiling.
        And the second parameter is just the output print, first parameter is the "is false, stop program"


std::is_base_of
    Checks for whether or not the first parameter is the base class of the second parameter. If the first parameter is the base class of the second parameter, return True. Otherwise, false.
    ::value is necessary here because std::is_base_of is a struct, and ::value is how you extract the value of it -- think of it as like a get function(), hence: std::is_base_of<Component, T>::value

std::make_unique
    make_unique is a kind of combination of 2 things: malloc and std::unique_ptr.
    std::make_unique<T>(std::forward<Args>(args)...), this creates an object of type <T> on the heap with the arguments we provided for it.
    It first calls new, and then returns a unique_ptr to that object created with new located on the heap.
    unique_ptr is JUST special in the sense that it will DESTROY the object when the ptr object goes out of scope.
    When the unique_ptr object goes out of scope, the underlying object is freed from the heap -- you do NOT have to delete/free it yourself, normal scope rules apply, it's kinda like it's on the stack!

std::forward
    std::forward is used for "PERFECT FORWARDING"
    Whenever you pass in a rvalue (just some hardcoded number or whatever, not an object) to a function, the function itself gives it a name so it becomes an lvalue
    However, std::forward allows you to differentiate between a passed rvalue and an lvalue -- it CHECKS how the arguments were originally passed into the function, whether it be a lvalue or rvalue.
    One of the reasons to do this is because it allows you to overload functions based on whether or not the arguments passed were an rvalue or lvalue -- you tie it with operator&& on variables.
        It's similar to std::move, but std::move SOLELY rips the underlying type into an rvalue, it DOES NOT allow you to check whether it's an lvalue -- std::forward is flexible.
    You HAVE to use the angled brackets to call std::forward: std::foward<theTypename>

    std::forward<Args>(args)...
        In this context, the ... is saying "aply std::forward<Args> to EVERY (args), and it UNPACKS all the types so it can pass every single argument in args to the constructor
            YOU MUST UNPACK IT WITH ..., so std::forward<>()... is the default way to invoke args to the constructor. Remember it!

operator&& within function parameters
    This is REQUIRED for std::forward -- it's called Universal References, and it preserves their EXACT type (lvalue/rvalue). In order to use std::forward, you NEED to use this.

std::move
    forces the object into an rvalue. this is useful for pointers as you can copy the address which the pointer is pointing to, NOT the address of the pointer thats pointing to that object.
    This is useful for resource transfers: in the example of a unique_ptr, since it goes out of scope and the object and itself WILL get deleted when it exits the function, in order to preserve that,
    we use std::move to essentially move ownership from the temporary unique_ptr to our member variable; the original object will get destroyed and be set to null after std::move.
        Also, unique_ptr doesn't allow copying, so we cant do ptr = unique_ptr, so to circumvent this, we have to get the underlying rvalue type, hence std::move
        Essentially, it TRANSFERS ownership of this object INSTEAD of duplicating it

dynamic_cast<>
    Dynamic cast is similar to static_cast, BUT instead of dynamic_cast checks at RUN TIME instead of COMPILE TIME (where static_cast converts at compile_time)
    This is primarily used for "downcasting" a base class into a derived class.
        Derived* d1 = dynamic_cast<Derived*>(basePtr);  // where basePtr is the base class, and derived is a type thats derived from the base class.
    IF it cannot be converted, it returns nullptr, so it's a good idea to check if d1 is nullptr to see if that cast occurs -- if it fails, it means the <type> is NOT derived from basePtr.


mutable keyword
    The mutable keyword is used to allow a const member function to modify the contents of a member variable.
    Usually, a const member function cannot modify the members of its struct AT ALL. However, mutable bypasses this.
        https://docs.vulkan.org/tutorial/latest/Building_a_Simple_Engine/Engine_Architecture/03_component_systems.html#_common_component_types
        This code snippet: the GetTransformationMatrix() function is const, and usually this function cannot modify the member variables.
        However, members transformationMatrix and transformationDirty are mutable:
        allowing GetTransformationMatrix's operations to modify the contents even though the function itself is const!

operator~ on functions
    ~ means it's a destructor:
        virtual ~Component() { }
    indicates it will execute the bracket code when the object goes out of scope -- this is used to clean stuff up after the destruction of the object
    So if we need to modify something when the object is destroyed, such as setting something else's state to zombie or destroyed to notify another object, then we can use the destructor to do that.
