Scene culling works by getting the planes (like walls) of the camera frustum (what the camera sees) and computing whether or not the OBJECT BOUNDs of some object lies inside the frustum or outside of it.
    If it's inside the frustum, don't cull the object; if the bounding "VOLUME" is outside the frustrum, cull the ENTIRE object.
        If we check against EVERY single vertex with a CPU, it'd be terribly slow (more of a GPU job), so we check one "point", which is the bounding.

    If, hypothetically, the bounds of some object IS peeking inside the frame, BUT some of the volume of the bounds IS outside the frustrum's view, we still render that object
        this is because otherwise the entire object itself would be peeking in and out of existence, as if we move our camera by like 0.01mm (just enough so that the "CENTER" of the bounding box is inside)
        and then the BOUNDING "POINT" is considered INSIDE, we could go back and forth and it'd force the object to be rendered.
            anyways, the idea is we're checking the entire radius of the object via a bounding box or a sphere, which is a box/sphere to encompass the entire object
                if the bounding boundries are present inside the frustrum, render the object.

The formula is: (x1 * x2) + (y1 * y2) + (z1 * z2)
= glm::dot( ( 0.76986258462, 0, 0.63820969439 ), (0.0828991, 34.9534, -5.1) )

The dot product tells us the "directional alignment"

If the dot product return is...
Positive: the vectors point in the same direction
Negative: the vectors point in opposite directions
If the return is EXACTLY 0: the vectors are perfectly perpendicular

In this case, the dot product tells us the offset of the plane (so we can line up the plane appropriately, see the desmos graph and fiddle around with = Offset)

IF you compute the dot product of a PLANE and a POINT on that plane, you get the offset (DISTANCE OF WHERE THAT PLANE IS LOCATED)

------------------------------------------
In summary: The ultimate reason we do this is because these vectors are then used to calculate a plane:
In order to calculate a plane, you only need 3 points in space:

glm::normalize(glm::cross(p1-p0, p2-p1));
    THIS tells the DIRECTION of the plane,

BUT in order to finalize the plane, we also need the OFFSET, which is calculated via the dot product of the plane's normal (direction) AND some point within that plane.
glm::dot(planeNormal, p0);
    p0 is ARBITRARY: it can be ANY point on the plane.

And in turn, you get a complete Plane struct: the offset, and the direction/normal.

------

The reason we do this is for our culling system:

Distance = (Normal dotproduct. ObjectPosition) − Offset

If distance is positive: object is past the wall we've established with the vectors -- CULL IT -- see: https://www.desmos.com/3d/zv3ucrneys
If it's negative: the object is outside the wall, so don't cull it.

Why? We can check whether or not a point lies on the plane by plugging in its coords within the plane's equation:
    For example: 0x + -0.906308y + 0.422618z = -33.8339, and the point 10, 60, 50
        If plugging the point into the equation above is 0: the point lies on the plane.
        However, the way we're checking is similar in spirit, but tells us whether a point is inside the walls essentially:

    ***USE THE DESMOS GRAPH TO CHECK POINTS YOURSELF AS A VISUALIZER***

Distance = (Normal dotproduct. ObjectPosition) - Offset

> dot product( 0x + -0.906308y + 0.422618z, 10, 60, 50 ) = -33.24758
    aka: 0(10) + -0.906308(60) + 0.422618(50) = -33.24758
> -33.24758 - Offset = -33.24758 - -33.8339 = 0.58632
Distance = 0.58632

IF our Frustum's plane's normals are INWARDS:
    Distance > 0: the point is infront of the plane -- render it.
    Distance = 0: the point lies precisely on the plane.
    Distance < 0: the point is behind the plane -- cull it.
IF our Frustum's plane's normals are OUTWARDS:
    Distance > 0: the point is behind the plane -- cull it.
    Distance = 0: the point lies precisely on the plane.
    Distance < 0: the point is infront of the plane -- render it.

A plane's normals are considered OUTWARDS if the points p0 -> p1 -> p2 -> p0 used to calculate the normal are counter-clockwise
    If it's clockwise, the plane's INWARDS.

Since our planes are outwards and distance is > 0, we cull it.

For the logic of code: iterate through the frustum's planes, run the formula Distance = (Normal dotproduct. ObjectPosition) − Offset for EVERY plane,
 if the distance is > 0 for EVEN JUST ONE PLANE, break the loop (like return or whatever): then IF the loop successfully exits, return true/render it.

    TLDR: ensure all the planes' normals directions are either inward or outward so we don't have to muddy up culling logic to account for a different plane's direction

For 3 planes point intersection (which can give us a specific point, not a slider of T), we can forego the manual calculation above and use Cramer's Rule.

Put the equations into a matrix (3x3)

|x1, y1, z1|
|x2, y2, z2|
|x3, y3, z3|

Then the column of offsets:
|d1|
|d2|
|d3|

Then, you create 3 "SUBSTITUTE MATRICES", where if you want to solve for X/Y/Z, you substitute the X/Y/Z column with the column of offsets:

To solve for X:
|d1, y1, z1|
|d2, y2, z2|
|d3, y3, z3|

To solve for Y:
|x1, d1, z1|
|x2, d2, z2|
|x3, d3, z3|

To solve for Z:
|x1, y1, d1|
|x2, y2, d2|
|x3, y3, d3|

Then you find the determinants of the Main Matrix, and the 3 determinants of the substituted matrices xyz

To solve for XYZ:
x = det(substitutedMatrix_xColumn) / det(mainMatrix)
y = det(substitutedMatrix_yColumn) / det(mainMatrix)
z = det(substitutedMatrix_zColumn) / det(mainMatrix)

Full code:
                    // Cramer's Rule
                    glm::vec3 offsetColumn ( viewPlane.offset, xPlane.offset, yPlane.offset ); // In the context of matrix multiplication, this is a mat3x1.
                    glm::mat3 inRowsNormals_main = glm::transpose( glm::mat3( viewPlane.normal, xPlane.normal, yPlane.normal ) );
                        // Transpose it so columns become rows: mat3 construction places them into columns, but we want | x1, y1, z1 | as a row, not a column

                    glm::mat3 inRowsNormals_x = glm::mat3( offsetColumn, inRowsNormals_main[1], inRowsNormals_main[2] );
                    glm::mat3 inRowsNormals_y = glm::mat3( inRowsNormals_main[0], offsetColumn, inRowsNormals_main[2] );
                    glm::mat3 inRowsNormals_z = glm::mat3( inRowsNormals_main[0], inRowsNormals_main[1], offsetColumn );

                    float z_intersection = ( (glm::determinant(inRowsNormals_z)) / mainMatrixDeterminant );
